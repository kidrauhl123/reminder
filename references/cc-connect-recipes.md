# cc-connect 调用配方

按需读取本文件。仅当调度后端是 cc-connect 时使用。所有示例都是要执行的 CLI；不要把命令发给用户当说明书，也不要让用户去敲 `/timer` 或 `/cron`。

`CC_PROJECT` 和 `CC_SESSION_KEY` 已由宿主注入时，不要再传 `--project` / `--session-key`。时间按本机本地时区。提醒默认接着当前会话（`reuse`），用户能直接接着聊。

## 一次性提醒

相对延迟用 `--delay`（如 `2m`、`30m`、`2h`、`1h30m`）。绝对时间用 `--at`：

```bash
cc-connect timer add --at "2026-08-26T15:00" --prompt "你正在执行用户已安排的一次性提醒。现在是提醒时间。请提醒用户提交材料。只发一条简短中文消息，先说行动；不要提及系统或定时任务。" --desc "提交材料"
```

不要用相对时间作为“明天下午三点”的持久计划；先换算成宿主本机时区的绝对时间再 `--at`。`--at` 不认 `+08:00` 这种偏移；本机是 UTC、用户在东八区时，把当地 13:00 写成 `2026-08-26T05:00`。命令成功后再告诉用户已排上，以及会在几点响。

## 可选事件：到点轻喊

群通知、orientation、讲座、破冰这类「不一定去」的场次，用 `event`。在开始时刻叫，不要提前催出门。prompt 里写地点，并写明去不去都行。

```bash
cc-connect timer add --at "2026-08-26T06:00" --prompt "你正在执行用户已安排的一次性提醒。现在请提醒主人：破冰 14:00 开始了，综合楼三楼室内篮球场，穿白T最好。去不去都行，不要催。称呼「主人」，语气软一点，可以带一点 emoji，但别油、别长篇。不要追问，不要创建其他任务，不要提及系统或定时任务。" --desc "破冰 综合楼三楼"
```

创建成功后立刻 `add-reminder --kind event`，把 `job-id` 写进库。用户问明天有什么时，这类和必做分开说。

## DDL 型任务：提前开始，而不是到点交付

用户说“周五下午三点提醒我交材料”“明天中午前要发报告”时，三点/中午通常是 DDL。除非用户明确说只要到点交付提醒，否则至少创建一个更早的行动提醒。

示例：用户说明天下午三点交材料，先安排明天 09:00 开始准备：

```bash
cc-connect timer add --at "2026-08-26T09:00" --prompt "你正在执行用户已安排的一次性提醒。用户明天下午三点需要提交材料；现在请提醒用户开始准备材料。只发一条简短中文消息；不要提及系统或定时任务。" --desc "准备提交材料"
```

若还需要临门一脚，可再加一条 DDL 前轻提示，例如 14:30：

```bash
cc-connect timer add --at "2026-08-26T14:30" --prompt "你正在执行用户已安排的一次性提醒。用户下午三点需要提交材料；现在请提醒用户检查材料是否齐全并完成提交。只发一条简短中文消息，不要制造压力，不要提及系统或定时任务。" --desc "检查并提交材料"
```

提前量不好判断时只问一个问题；否则用低风险默认值，并在确认里说明“我提前到 X 点叫你先开始”。

## 模糊目标

对象不明且会影响内容时，先问一句再创建。提醒写清楚做什么，不要只写“该学习了”。

## 重复提醒

只支持五段 cron，没有 `every 2h` 这种从现在起的间隔。需要“每隔两小时”时，用对齐钟点的表达式（如 `0 */2 * * *`），并在确认里说明是整点对齐，不是从现在起计时。

每天 09:00 晨间启动：

```bash
cc-connect cron add --cron "0 9 * * *" --prompt "你正在执行用户主动设置的每日晨间启动。请用中文发一条低压力的简短消息，请用户只选出今天最重要的一件事。不要假装知道用户今天的日程，不要创建其他任务。" --desc "每日晨间启动"
```

每晚 22:30 回顾：

```bash
cc-connect cron add --cron "30 22 * * *" --prompt "你正在执行用户主动设置的每日晚间回顾。请用中文发一条不评判的简短消息，让用户用一句话回答今天完成了什么或卡在哪里；若精力不足，允许直接结束今天。不要推断完成情况，不要创建其他任务。" --desc "每日晚间回顾"
```

创建前先 `cc-connect cron list`，避免同义重复。长期节奏必须用户主动要求。

## 推迟当前提醒

用户在提醒下回复“十分钟后再叫我”时：

1. 用 `--delay 10m` 新建一次性 timer，内容保留原行动。
2. 不修改原有重复 cron；已触发的一次性 timer 也无需删除。
3. 回报新的准确触发时间。

```bash
cc-connect timer add --delay 10m --prompt "你正在执行用户已安排的一次性提醒。现在请提醒用户继续：提交材料。只发一条简短中文消息，先说行动；不要提及系统或定时任务。" --desc "提交材料（推迟）"
```

## 修改、暂停与取消

```bash
cc-connect timer list
cc-connect cron list
cc-connect timer del <id>
cc-connect cron del <id>
cc-connect cron edit <id> enabled false
cc-connect cron edit <id> enabled true
cc-connect cron edit <id> cron_expr "0 10 * * *"
```

多个任务同名或语义接近时，不要自行选择。向用户展示名称和时间，让用户用一句话选定。

## 自包含提示词检查

到点后的 prompt 可能落在新会话或闲置轮转后的会话里，至少要写明：

- 这是用户已经安排的提醒，不需要再次确认。
- 要提醒的具体行动。
- 用户已经提供的截止时间或原因（若有）。
- 使用中文、期望的语气与长度。
- 不追问、不创建其他任务、不暴露内部信息。

不要写“提醒他刚才说的那件事”或“根据上文处理”。
