# cronjob 工具配方

按需读取。仅当宿主提供 `cronjob` 工具时使用；cc-connect 见 [cc-connect-recipes.md](cc-connect-recipes.md)。示例是工具参数示意，调用实际工具，不要把 JSON 原样发给用户。

## 单次提醒

将相对时间换算为用户时区中的绝对时间，优先使用带 UTC 偏移的 ISO 8601：

```json
{
  "action": "create",
  "name": "提交材料",
  "schedule": "2026-08-22T15:00:00+08:00",
  "prompt": "你正在执行用户已安排的一次性提醒。现在是提醒时间。请提醒用户提交材料。只发一条简短中文消息，先说行动，再给一个可以立刻开始的最小动作；不要提及系统或定时任务。",
  "skills": ["reminder"]
}
```

通常省略 `deliver`，让结果回到创建任务的原会话。不要传已过时的 `attach_to_session`。不要用相对时间作为单次提醒的持久计划，以免基准时间产生误解。

## DDL 型任务：提前开始，而不是到点交付

当用户说“周五下午三点提醒我交材料”“明天中午前要发报告”时，三点/中午通常是 DDL，不是开始工作的最佳时间。除非用户明确说只要到点交付提醒，否则至少创建一个更早的行动提醒。

示例：用户说“明天下午三点提醒我交材料”，当前判断这是 DDL，先安排明天上午 09:00 开始准备：

```json
{
  "action": "create",
  "name": "准备提交材料",
  "schedule": "2026-08-22T09:00:00+08:00",
  "prompt": "你正在执行用户已安排的一次性提醒。用户明天下午三点需要提交材料；现在请提醒用户先开始准备材料。只发一条简短中文消息，建议先打开材料清单或找出要提交的文件；不要提及系统或定时任务。",
  "skills": ["reminder"]
}
```

如果用户可能还需要临门一脚，可再创建一个 DDL 前轻提示，例如提前 30 分钟检查并提交：

```json
{
  "action": "create",
  "name": "检查并提交材料",
  "schedule": "2026-08-22T14:30:00+08:00",
  "prompt": "你正在执行用户已安排的一次性提醒。用户下午三点需要提交材料；现在请提醒用户检查材料是否齐全并完成提交。只发一条简短中文消息，不要制造压力，不要提及系统或定时任务。",
  "skills": ["reminder"]
}
```

若任务规模不明、提前量不好判断，只问一个问题；否则采用低风险默认值并在确认里说明“我提前到 X 点叫你先开始”。

## 模糊目标：转成第一步

当用户说“提醒我学习”“提醒我整理一下”“我要把项目推进一下”时，不要把模糊目标原样写进提示词。先生成一个能立刻开始的动作；必要时只问一个澄清问题。

示例：用户说“今晚提醒我学习”，没有说明学什么，但低风险默认可以是打开资料并读 10 分钟：

```json
{
  "action": "create",
  "name": "学习 10 分钟",
  "schedule": "2026-08-22T20:00:00+08:00",
  "prompt": "你正在执行用户已安排的一次性提醒。用户想在今晚学习；现在请提醒用户先打开要学的资料，读 10 分钟，并标出一个不懂的问题。只发一条简短中文消息，不要说教，不要提及系统或定时任务。",
  "skills": ["reminder"]
}
```

示例：用户说“提醒我推进项目”，但项目对象不明，且对象会影响提醒内容，应先问一句：

```text
你想推进哪个项目？如果不想细分，我可以今晚 8 点提醒你先列出这个项目的下一步。
```

用户接受默认后再创建：

```json
{
  "action": "create",
  "name": "列出项目下一步",
  "schedule": "2026-08-22T20:00:00+08:00",
  "prompt": "你正在执行用户已安排的一次性提醒。用户想推进一个项目；现在请提醒用户先写下这个项目的下一步，并只选一个 10 分钟内能开始的动作。只发一条简短中文消息，不要说教，不要提及系统或定时任务。",
  "skills": ["reminder"]
}
```

## 重复提醒

每天 09:00 的晨间启动：

```json
{
  "action": "create",
  "name": "每日晨间启动",
  "schedule": "0 9 * * *",
  "prompt": "你正在执行用户主动设置的每日晨间启动。请用中文发一条低压力的简短消息，请用户只选出今天最重要的一件事，并建议先做一个十分钟内能完成的起步动作。不要假装知道用户今天的日程，不要创建其他任务。",
  "skills": ["reminder"]
}
```

每晚 22:30 的回顾：

```json
{
  "action": "create",
  "name": "每日晚间回顾",
  "schedule": "30 22 * * *",
  "prompt": "你正在执行用户主动设置的每日晚间回顾。请用中文发一条不评判的简短消息，让用户用一句话回答今天完成了什么或卡在哪里；若精力不足，允许直接结束今天。不要推断完成情况，不要创建其他任务。",
  "skills": ["reminder"]
}
```

Cron 表达式使用宿主配置的时区。创建前确认用户已主动要求这个长期节奏，并先 `list` 检查是否已有同义任务。

## 推迟当前提醒

用户在提醒下回复“十分钟后再叫我”时：

1. 根据当前时间计算新的绝对 ISO 时间。
2. 创建一个新的单次提醒，内容保留原行动。
3. 不修改原有重复任务；已触发的单次任务也无需删除。
4. 回报新的准确触发时间。

## 修改、暂停与取消

先获取真实任务列表：

```json
{"action": "list"}
```

找到唯一匹配的 `job_id` 后再调用：

```json
{"action": "update", "job_id": "真实 ID", "schedule": "0 10 * * *"}
```

```json
{"action": "pause", "job_id": "真实 ID"}
```

```json
{"action": "resume", "job_id": "真实 ID"}
```

```json
{"action": "remove", "job_id": "真实 ID"}
```

多个任务同名或语义接近时，不要自行选择。向用户展示名称和时间，让用户用一句话选定。

## 自包含提示词检查

定时任务运行在新的会话中，提示词至少要写明：

- 这是用户已经安排的提醒，不需要再次确认。
- 要提醒的具体行动。
- 用户已经提供的截止时间或原因（若有）。
- 使用中文、期望的语气与长度。
- 不追问、不创建其他任务、不暴露内部信息。

不要写“提醒他刚才说的那件事”或“根据上文处理”；Cron 看不到创建任务时的聊天记录。
