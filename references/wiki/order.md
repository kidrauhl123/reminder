# 生活有条理

## 何时打开

用户说乱、事情太多、脑子里堆着、想建立系统、不知今天先做啥。单件有钟点的事 → `SKILL.md` 事项类型。开不了头 → [procrastination.md](procrastination.md)。钱乱且在谈理财 → [wealth.md](wealth.md)。

## 一起想

条理的目标是**少在脑子里开着标签页**，不是把一天填满、也不是更漂亮的计划 App。

三层就够（Allen GTD 的精神，不必教用户缩写）：

- **日历**：有钟点的场次和截止（本 skill 的 event / deadline）。
- **下一步**：具体动作（action / 意愿的 min_action）。
- **有朝一日**：想做但现在不排（intention，不到点喊）。

Covey 要事第一：先后果大的，再可选。当天操作已经写在 `SKILL.md`「轻量规划」——本页不另造一套每日流程。

系统癖是反条理：标签、四象限表、复杂周回顾，维护成本会把人压回去。外部大脑可以是这套提醒库和这场对话，用户不必先成为会计划的人。

晨间启动 / 晚间回顾只有用户主动要才开。生活锚点（吃饭、课、睡、通勤）是现成骨架，新习惯往上挂，不另造理想作息表。

## 落地

- 「我很乱」：先 `today`，1 件必须 + 最多 2 件可选，其余明确暂不处理。不要趁机重建人生系统。
- 用户倒出一堆事：逐条归进日历 / 下一步 / 有朝一日，不要求他们先分类。
- 想「变有条理」但没点名哪一件：记一条 intention，min_action 极小（例如「把明天有钟点的事说给我」），按 `SKILL.md` 挂那一条最小提醒；不要订阅每日复盘。已经在过的生活意愿（早睡、健身）不是「有朝一日」，要挂到点消息。

## 边界

- 不 invent 课表或空闲。
- 不把成长线做成盖过 DDL 的第二套日程。
- 不推销复杂方法论。
